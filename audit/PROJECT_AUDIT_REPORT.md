### B. 当前模型核心参数

- 架构：2×Conv2d(3×3, 16ch) + ReLU → Flatten(576) → FC(64) + ReLU → 双头 FC(235)/FC(1)；共享 backbone；无归一化/残差/注意力/RNN
- 参数量：**55,468**（conv 3,200 / hidden 36,928 / actor 15,275 / critic 65），FP32 理论 221,872 B
- 输入 shape：float32 [B, 6, 4, 9]；特征通道：座风 one-hot、圈风 one-hot、手牌温度计 ×4
- 输出：235 维 masked logits + 标量 V；部署 greedy argmax
- 推理耗时：CPU 单决策管线 0.04 ms；MPS batch1024 前向 0.52 ms（~2M states/s）
- BC 数据规模：814,957 样本（IJCAI 563,257 + teacher 251,700），train 732,211 / val 82,746（**切分泄漏**）
- PPO 训练规模：300 迭代 × 8 actor = 2,400 局 / 846,109 决策步 / 10,401 次 optimizer step，127.6 s
- 当前实测性能：vs random +0.186（CI [0.091, 0.280]，16 胜 82 荒 2 负/100 局）；vs teacher −0.206（CI [−0.309, −0.102]）；配对 RL−BC vs random +0.138（CI [0.030, 0.245]，显著）

### C. 关键风险（按严重程度）

**P0-1 IJCAI 数据 train/val 牌墙泄漏（已复现）**
- 证据：前 3000 局仅 126 个独立 srand（牌墙），每墙 24 局（4 选手座位排列复式）；`game_id%10` 切分使 100% val 局与 train 共享牌墙；**92.78% val 样本与 train 样本 (obs,mask,action) 逐字节相同**（audit/data_stats.json）。
- 影响：val loss/acc 不能用于模型选择与泛化声明；有效训练数据被重复样本膨胀（去重后唯一决策点远少于 732k）。**实测量化影响有限**：全新牌墙上 BC play acc 32.78% ≈ 泄漏 val 32.41%（小模型记忆不动），故第一轮数值大致可代表真实水平，但方法学必须修复。
- 修复：按 srand 分组切分（整墙进 train 或 val）；replay.py 提取 srand 写入 shard/meta，重新生成（3000 局仅 3.3 s）。工作量 ~1-2 h。

**P1-1 BC 只训练 actor 头，卷积/隐藏层保持随机初始化（已复现）**
- 证据：`train_bc.py:122` 优化器仅含 `model.actor.parameters()`；权重比对：bc_v1 的 conv.0/conv.2/hidden.0/critic == seed-0 初始化（audit/inventory.json）。
- 影响：当前 BC 实质是"随机特征 + 线性探针"，play acc 32.8% 是在冻结随机 backbone 下取得的；修复后 BC 质量预期显著提升，且改变后续 RL 起点。第一轮"BC 预训练"结论仍成立但被低估。
- 修复：优化器改为 `model.parameters()`（一行）。工作量 <0.5 h + 重训 ~1 min。

**P1-2 输入信息严重不足（代码证据）**
- 证据：`features.py:9-17` 仅用座风/圈风/手牌；SeatView 已维护四家弃牌历史 `history`、四家副露 `packs`、牌墙余量 `tileWall`、公开牌计数 `shownTiles`（observation.py:38-47）全部未进网络。模型看不到对手行为与局面阶段。
- 影响：鸣牌/防守/番种规划无从学起；chi val acc 仅 15.5-26.4%；参考实现用 102 通道 + 107 维候选牌质量先验。
- 修复：在 encode 中增加公开信息通道（无需改裁判/协议，训练与部署共用同一函数）。工作量 ~1-2 天含测试。

**P1-3 评估检验力不足且非严格复式（已复现）**
- 证据：BC vs random +0.048 CI [−0.006, 0.102] 含 0；RL−BC vs teacher CI 含 0；同 seed 仅保证同牌墙，对手动作随受控策略分歧（evaluate.py 交互采样）；无置信区间报告（第一轮）。
- 影响："BC>random"仅配对检验与胜局数支持；"RL>BC vs teacher"未达显著；小效应可能被噪声淹没（参考：PiggyQwQ 实测 200 局噪声 ±6.5/局）。
- 修复：实现冻结对手复式 arena（同墙四座位轮换、配对差±SE，≥500 组，参考 LegendXct arena）。工作量 ~1 天。

**P1-4 纯共享策略自对弈，无防退化机制（代码证据 + 参考病理）**

### D. 模型升级判断

1. **当前参数量：55,468**（实测，MODEL_SPEC §3）。
2. **是否太小？** 相对参考实现（14.5M/19.26M）小 260-350 倍，几乎必然偏小；但"太小"不是当前第一瓶颈——冻结 backbone 的 BC 与 6 通道输入先于容量限制能力。
3. **最大瓶颈在哪？** 排序（证据强度递减）：① BC 优化缺陷（代码证实）→ ② 输入信息不足（代码证实 + 参考消融支持）→ ③ 容量/架构（推测，需消融）。参考证据：vec 特征 +2.32pp、GELU +6.22pp、2.3× 参数双分支无收益（LegendXct）；完美信息 critic R² 仅 +0.010（信息不完美在其表征下非主瓶颈）。
4. **是否值得扩大网络？** 值得，但**先修 BC、补特征，再扩容**；否则扩容收益被前两者掩盖。
5. **建议多大？** 阶段 1：~0.5-1.5M（ResNet w64 × 4-6 块 + 丰富特征；实测候选 w64×4+双头+vec = 1.32M）；阶段 2：3-15M（需 ≥10M 级决策点数据 + GPU；>5M 部署用 fp16 常驻，参考 14.5M → 182.6MB）。不预设越大越好。
6. **值得借鉴的架构/配方**：PreAct ResNet + GroupNorm + GELU；空间张量 + 每候选弃牌质量先验 vec 双输入拼接；温度计编码与未见牌计数；花色置换增广（排除花色不对称番种局）；合法动作内标签平滑；AdamW + warmup/cosine；复式 arena 评测；RL 的 KL 锚定 + 风格化对手池 + eval-best 地板 + 向听势能塑形（候选）。
7. **下一轮最优先**：修 P0 切分 + P1-1 BC 全模型训练（合计 <2 h，立即提升数据可信度与 BC 质量）→ 丰富特征 → 干净 BC + 2×2 消融 → arena ≥500 组 → 带锚定的 RL 放量 → 数据扩量（IJCAI 全量 + 官方 SL data.txt 95k 局，PiggyQwQ 使用的来源）。
8. **远程 GPU 是否必要？** 阶段 1（≤1.5M、≤2.5M 样本）**不需要**：外推 BC ~6-12k samples/s（MPS）→ 2.3M×8 epoch ≈ 30-60 min；RL learner 更新约 3-5× 变慢 → ~1-1.5 s/迭代，2000 迭代 ~40 min（外推，需实测）。阶段 2（14.5M + 18M 决策点 × 20 epoch）**需要** GPU（参考训练规模远超本机合理时长）。

## 7. PPO 强化学习

### 7.1 BC→PPO 衔接（已验证）

resume 加载完整 policy（actor+critic+backbone）；BC checkpoint 优化器为空 Adam(lr 3e-4) → 无陈旧动量；hidden/capacity 校验；RNG/episode_cursor 恢复；300 迭代 parameters_changed 全 true；rl 权重相对 bc 全面变化。critic 在 BC 阶段未训练（设计），PPO 前 50 迭代 value_loss 0.0087→0.0046 正常拟合。

### 7.2 算法细节（实证通过）

clip PPO + GAE(γ0.99, λ0.95, 决策时钟) + advantage 归一化 + grad clip 0.5 + entropy 0.01；终局 bootstrap 0、荒庄奖励 0、奖励/32 固定缩放（无 running norm）；old-logp  detached 固定（ratio≡1 检验）；每座位独立轨迹（key 含 agent_id），GAE 逐轨迹计算后才拼接 batch——**无跨玩家 GAE 污染**；奖励落在每座位最后决策（含放铳者）——时序正确；检验见 AUDIT_EVIDENCE §6（误差 ≤1e-6）。

### 7.3 对手与奖励

四座位共享正在更新的策略 = 完全共享自对弈；无固定/历史对手；终局零和（自摸 3×(8+fan) vs 3×−(8+fan)；点和 24+fan / −8−fan / −8×2；荒庄 0；非法 0 和）；无辅助奖励。风险：对弱自对弈分布过拟合（参考已记录），见 P1-4。

### 7.4 第一轮结果可靠性

counters 与日志逐项吻合；指标定义：1 迭代 = 8 局（8 actor×1）= ~2700 决策步 = 3×ceil(steps/256) ≈ 33 optimizer steps；2400 局 = 2400 独立种子/牌墙；"非荒庄率"= 非零奖励轨迹占比（座位级）。**经核实座位级=局级**：零和奖励下每个分胜负局四座位同时非零（300/300 迭代非零计数均为 4 的倍数），全局 401/2400=16.71%，first50 12.75%→last50 23.25% 可直接读作局级比例。300 迭代规模小，结论"RL 有改善"仅在 vs random 配对显著；vs teacher 不显著。

## 10. 性能瓶颈与算力

实测（AUDIT_EVIDENCE §2/§6）：
- BC：MPS batch1024 ~118k samples/s（55k 模型）；CPU 小 batch 更快（传输开销）。
- PPO 8 actor：0.47 s/迭代 = collect 39% + GAE 6% + **update 53%**；~17 局/s。
- 模型前向在采样中占比小（env 0.032 ms vs forward 0.103 ms/联合步，但 actor 端 TensorDict/采样开销另计）；learner 更新是最大单项。
- MPS 对 learner 有 ~4× 前向加速潜力（batch256），整体迭代预计 ~1.7×（外推）。
- 扩大模型后：learner 更新与 BC 首先变慢（参数 ×27 → 更新约 ×10-20，外推）；采样端 actor 前向也变慢但 batch1 绝对值仍小。
- 百万局估算（按局数）：17 局/s → 1M 局 ≈ 16.4 h（当前模型）；30 万局 ≈ 4.9 h；10 万局 ≈ 1.6 h。1.3M 模型外推 ~4-6 局/s → 1M 局 ≈ 46-70 h（需实测）。
- 远程 GPU 收益点：阶段 2 大模型 BC（18M 样本×20 epoch）与大规模 RL；阶段 1 本机足够。
