# 掼蛋示例

先阅读上级 README，把命令中的游戏名改为 `guandan`。

两副牌 108 张，四人各 27 张，对家合作。支持单/双贡、抗贡、还贡、红桃级牌配牌、常规牌型、炸弹、同花顺和四王炸。只学习出牌；`heuristics.py` 进贡选最大非配牌，还贡选最小合规牌；极端无小牌手牌采用最小非配牌作为兜底。训练按随机种子轮换级牌及无贡/单贡/双贡，初始头游/末游默认为 0/3，不模拟跨局升级。

`gamecore/rules.py` 负责比较与校验，`engine.py` 负责轮转、接风、贡还牌及结算。出完牌玩家等待全局结束后一起获得团队奖励，不会提前切断轨迹导致奖励丢失。

`features.py` 输出 `obs[346]`、`candidates[capacity,108]` 和 `action_mask[capacity]`。每个候选动作同时编码实际出的牌和待压牌；配牌替代关系由规则校验。状态含私有手牌、四家已出牌、当前待压牌、剩余张数、级牌；主花色位置保留为常量。可扩展最近行动玩家、出完顺序和历史信息。

候选动作生成保留每个牌型的一种规范物理实现，并非穷举所有配牌选择或等价牌组合；容量默认 128，溢出后确定性保留子集并统计。

第一位出完牌者的队伍获胜，队友第二/第三/第四出完对应训练奖励 +3/+2/+1，另一队相反。评估控制一对座位，对手从相同候选集合均匀随机选择。它不代表完整跨局升级赛强度。

部署文件 `guandan_bot.zip` + `guandan_model.pt`，使用 JSON 默认交互与长时运行。`botzone/session.py` 对贡还牌及公共 history 去重，并支持长时进程丢失后的完整历史重放。建议优先修改特征和网络，规则候选修改后运行 `tests/test_rules.py`。
