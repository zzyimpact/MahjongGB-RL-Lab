# 双升示例

先阅读上级 README。命令使用 `tractor`。

每局洗两副牌，共 108 张，四人各 25 张，剩余 8 张给庄家扣底。发牌时的报主/抢主使用 `heuristics.call_card` 人工策略；默认扣回收到的 8 张底牌。只有出牌决策交给 PPO。默认初始级别随种子轮换，不做跨局升级；简单报主策略不会主动叫无主，但牌规则和 Bot 能读取无主局。

`gamecore/engine.py` 管理准备和阶段，`reference.py` 是规则裁判。`actions.py` 仅根据当前玩家私有手牌和公共历史生成合法候选，`features.py` 输出 `obs[346]`、`candidates[capacity,54]`、`action_mask[capacity]`。状态包含手牌、四家已出牌、首家出牌、剩余张数、级别和主花色；模型分别编码状态/候选并打分。当前未编码庄家相对位置和本墩其他跟牌，是学生可扩展项。

候选动作不主动甩牌，允许对子、单张与生成器覆盖的拖拉机；对子拆单、连续对子不同子段及等价物理牌不是穷举。跟对手甩牌按最大结构优先生成并检查同花/对子约束。罕见复杂甩牌需要更多平台实战回放验证，候选组合多时也可能较慢。容量默认 128，超出后确定性选取覆盖排序范围的子集。

终局训练奖励：闲家 `(闲家总分-80)/80`、庄家取相反数；两位队友奖励相同。中间每墩分数不重复发奖；扣底按最后首家牌型长度计算倍数。因此恰好 80 分时训练奖励为零，不能把零奖励等同于平台平局；这不是平台对局得分的直接复刻。

牌编号沿用课程原例和 Wiki 示例代码的 `s,h,c,d` 花色顺序。部署文件 `tractor_bot.zip` + `tractor_model.pt`，使用 JSON 默认交互与长时运行。`botzone/session.py` 从完整或增量 history 重建公开出牌，避免重复扣手牌。

可优先修改 `features.py`、`model.py`、`configs/default.json`；改准备阶段策略用 `heuristics.py`，训练与 Bot 同时生效。改 `actions.py` 时保留候选顺序一致性和 mask 对齐，重跑 `tests/test_rules.py`。
